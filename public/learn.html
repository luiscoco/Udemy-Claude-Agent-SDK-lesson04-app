01

Follow the five-stage loop

Prompt → model response → tool execution → feedback → repeat or final result. The SDK owns orchestration; your iterator observes it.

02

Separate messages, blocks and turns

Several assistant messages may share one response ID. Partial stream events are not turns. Read the SDK num_turns separately from observed response groups.

03

Correlate requests and feedback

assistant tool_use.id links to user tool_result.tool_use_id. The interface shows these identifiers and safe descriptions instead of raw credentials or hidden reasoning.

04

Observe real execution and approvals

Read/Edit/Glob/Bash availability is separate from allowedTools pre-approval and disallowedTools. Hooks observe and guard real calls; they do not fabricate a fixed four-turn script.

05

Experiment with limits and effort

Compare a normal repair with maxTurns: 1, change the SDK budget, and try supported low/high effort. A stopped run stays a stopped run.

06

Handle the actual final outcome

Inspect subtype, stop_reason, num_turns, usage, estimated cost and session ID. Continue iteration to completion and preserve an observed error result if the runtime then closes.

Three real experiments

  • Repair: run the failing tests, inspect code, edit auth.ts and run the tests again.
  • One-turn limit: force maxTurns: 1 and preserve error_max_turns rather than reporting transport failure.
  • Read-only inspection: remove Bash/Edit, inspect two files, and observe any shared response IDs or actual tool overlap.

The presentation’s four-turn trace is illustrative. This app never manufactures four turns or assumes every message is a turn. The final SDK num_turns and observed response groups are displayed separately.

Tools and concurrency

Built-in tools include Read/Edit/Write, Glob/Grep, Bash, web tools and orchestration tools. This app enables only those needed for the chosen local task. Read-only requests may overlap when the model requests them together; mutation scheduling is owned by the runtime. This lesson provides no custom MCP tool. The slides’ readOnlyHint annotation is a custom-tool extension exercise, not a feature silently implemented here.

The iterator returns observable events; your handler can update a UI or cancel a run. It does not manually drive the next model/tool cycle. Assistant text is not hidden chain-of-thought.
