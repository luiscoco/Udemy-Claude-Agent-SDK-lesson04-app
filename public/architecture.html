01

1. Choose scenario and loop limits

Student → Host observer. The selected controls become validated SDK options, not a simulated scenario playback.

02

2. Reset auth.ts and test fixtures

Host observer → Demo tools. The host restores a reproducible demo, including immutable test and package files.

03

3. query(prompt, options)

Host observer → Agent SDK. One query object owns the whole model/tool loop.

04

4. Yield system/init and partial events

Agent SDK → Host observer. The host observes lifecycle and optional partial events without treating each as a turn.

05

5. Send prompt and tool definitions

Agent SDK → Claude API. The runtime sends the task with available tool definitions to Claude.

06

6. Request one or more tools

Claude API → Agent SDK. The model chooses actual calls. Multiple content blocks may share a response ID.

07

7. Apply hooks and run permitted tools

Agent SDK → Demo tools. Hooks observe and guard the calls. Only auth.ts edits and exactly npm test are permitted in repair mode.

08

8. Return execution feedback

Demo tools → Agent SDK. Tools return results to the SDK. A failing npm test is useful feedback, not automatically a failed overall run.

09

9. Yield user/tool_result with matching ID

Agent SDK → Host observer. tool_result.tool_use_id links back to the assistant tool_use.id.

10

10. Send feedback; repeat if needed

Agent SDK → Claude API. The SDK performs the next model interaction itself; the host does not implement a manual Messages API loop.

11

11. Yield typed final result and metadata

Agent SDK → Host observer. The stream yields success or an error subtype with cost/usage/session metadata. Iterate through any trailing events.

12

12. Independently check actual auth.ts

Host observer → Demo tools. Trusted host checks verify the resulting file even after a limit or read-only success.

13

13. Show trace, outcome and evidence

Host observer → Student. Students compare final SDK status, response grouping, tool IDs, actual changes and independent checks.
