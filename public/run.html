01

Install and configure the application

Use Node.js 24+ and npm. Git for Windows/Git Bash may be required on Windows. Keep optional dependencies enabled for the SDK’s runtime. This lesson uses TypeScript and Node tests; Python is not needed.

git clone https://github.com/luiscoco/Udemy-Claude-Agent-SDK-lesson04-app.git
cd .\Udemy-Claude-Agent-SDK-lesson04-app
npm ci

In the original presentations workspace, use cd .\agent-sdk\lesson04-agent-loop instead of cloning. Create a local configuration file without overwriting an existing one:

if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
ANTHROPIC_API_KEY=your_api_key
CLAUDE_MODEL=claude-sonnet-4-6
PORT=3104

If needed on Windows, set CLAUDE_CODE_GIT_BASH_PATH=C:/Program Files/Git/bin/bash.exe. The SDK does not load .env itself; the web and sample:env commands load it explicitly. A key set in the shell takes precedence. Keep real keys out of source.

02

Run a normal repair

npm start
# Open http://127.0.0.1:3104

Keep the terminal open. Choose Repair auth.ts, keep low effort and partial messages on, then click Run agent loop. The initial file has three failing cases and one passing case. Watch system/init, assistant tool requests, user feedback and a final result. A valid repair changes auth.ts and passes 4/4 independent checks.

03

Hit the turn limit deliberately

After the normal run finishes, choose Hit maxTurns: 1. The preset enforces 1 on the server too. Run again and inspect the actual final subtype, cost, usage and stop reason. The task starts with npm test, so the limit experiment has insufficient room for the full repair cycle. Do not count a partial event, content block or hook as a separate turn. Tool order remains an actual model decision.

04

Inspect read-only execution and compare effort

Choose Read-only inspection. Its prompt requests two file reads, and its tools exclude edits and shell commands. Observe request/result IDs and response group numbers. If hooks interleave, report the overlap you actually observed; do not assume two requests always run concurrently.

Repeat the same task with low and high effort to compare outcomes and estimated cost. Keep other controls fixed for a meaningful comparison. This app offers two supported effort levels for the configured model, rather than claiming every model supports every level from the slides.

05

Explore partial messages, budget and project settings

Partial messages are requested with includePartialMessages. The trace hides those rows by default but counts them; use Show partial events to reveal them. Disabling the request produces no partial-message requirement. Lower maxBudgetUsd to observe an actual budget outcome; the response crossing the estimate threshold can still incur cost. Load project settings opts into settingSources: ["project"] and the bundled classroom CLAUDE.md. It is off by default. Session IDs do not imply persistence or a working resume UI.

06

Run and test from the terminal

Same-shell authentication:

$env:ANTHROPIC_API_KEY = "your_api_key"
npm run sample -- repair low
npm run sample -- limit low
npm run sample -- inspect high

For explicit file loading, use:

npm run sample:env -- repair low
npm run sample:env -- limit low
npm run sample:env -- inspect high

npm test
npm run build:client
python scripts/build-pages.py

Python is optional only for regenerating the teaching pages; it is not used by the app or its regression checks. Each model run can incur API usage. Starting the server does not call the API. Stop it with Ctrl+C. A duplicate app start prints its URL; another port listener requires stopping that service or changing PORT. Restart after configuration edits.
